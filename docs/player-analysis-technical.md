# 短线王 · 选手分析｜技术设计与验收

**V1.0 · 2026-11-22**　需求基线：[产品需求文档](player-analysis-product.md)。先看本节的实际交付；后文保留完整设计与后续接入目标。

### 当前代码与数据通道

**未报名可见榜单。** 首次连接时，参赛记录无法核验也可以读取当前页实际展示的信息。逐页完成后，以比赛和交易日为键独立写入 `sync.sqlite` 的 `visible_days`，工作台可展开查看。该路径不创建参赛绑定。2026-11-22 使用未报名账号实采官方年赛 11 月 20 日榜单，共 37 页、1,810 名选手，排名从 1 至 1,810。每行都有累计收益，1,469 行有当日收益，1,485 行有仓位，219 行明确空仓，未取得具体持仓股票代码。

**官网登录排查（2026-11-22）。** 手机号登录在点击「获取验证码」后由官网弹出安全验证，用户手动滑动后显示「验证失败，请刷新」。同一账号在采集窗口通过官网微信扫码后进入官网。两次日常 Chrome 登录均未出现滑块。现有观测无法确定短信验证的服务端失败原因；用户可将失败时间及弹层左下角的 CertifyId 提供给淘股吧核查。采集进程看到官网明确显示该错误时，在本机工作台反馈提示及可见查询编号，继续等待用户完成官网登录。[验证查询编号说明](https://help.aliyun.com/zh/captcha/captcha2-0/product-overview/basic-concepts)

**主流程。** 本机 `connect` 任务打开用户填写的比赛。用户完成官网登录后，若官网将浏览器带到首页，采集程序在同一会话返回原比赛一次。比赛详情尚未显示榜单时，程序选择页面上唯一可见的「选手列表」。工作台依次反馈榜单识别、参赛账号核验、读取日期和同步结果。程序在该浏览器中读取官方参赛卡 HTML，核对比赛 tid、选手账号与战绩序号，再把同一个 Page 交给 `readDays`。读取器依次展开选手、翻页，写入前再次检查赛事、账号、交易日和参赛卡。一个交易日读取成功后，本地 SQLite 发布数据版本。首次连接与后续盘后任务使用同一个读取器。

**默认浏览器的已有标签页。** 已核验账号可在工作台获取本场读取书签。在已登录的官网比赛页点击书签即可运行项目的页内读取器。读取结束后点「送回短线王」打开本机接收页。两个窗口用一次性随机值、固定目标 origin 和窗口引用校验消息，只传本次结构化快照。接收页通过现有 previewImport 检查本机绑定账号、赛事、交易日与覆盖，再由用户确认入库。浏览器隔离窗口或禁止弹窗时仍可保存 JSON。盘后无人值守任务使用项目管理的浏览器会话。

**系统默认浏览器。** 本机 POST `/view/player_sync` 的 `openInBrowser` 动作校验比赛链接，并从赛事 ID 生成官网 HTTPS 地址。Windows 使用系统 URL 关联，macOS 使用 `open`，Linux 使用 `xdg-open`。此动作仅打开网页。页面单独提供后台同步配置。

**本机独立同步。** 一级入口通过 GET/POST `/view/player_sync` 查看状态、连接比赛、立即同步、查看报单原图或设置定时。登录窗口由本机 Edge 或 Chrome 打开。Playwright Core 使用独立的持久化配置目录；Windows 上位于 `%LOCALAPPDATA%/Askill/contest-browser/<数据区摘要>`，与项目数据备份分开。用户在官网输入密码和验证码。工作台只读取当前可见的账号标识，每次核对该场参赛卡与战绩序号。[Playwright 持久化上下文](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context)

**采集与恢复。** `player_sync_worker.ts` 由本机服务或当前 Windows 用户的任务计划程序启动。每个项目数据区同一时间只使用一个比赛浏览器。`player-analysis/sync.sqlite` 记录赛事、计划时间、任务心跳和最后成功日期。Windows 任务按本机时间周一至周五运行，启用错过时间后补启动。工作台关闭后仍可运行，电脑需开机且用户已登录。首次同步取官网可确认的最近交易日，后续重查上次成功日期及其后的可见交易日。整天采集成功后才发布，中断后重读未完成的交易日。长期离线后的补采范围取决于官网当前能选择的日期。[Windows 任务设置](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasksettingsset)

**验收边界。** 已在隔离浏览器中测试关闭再打开浏览器后复用测试会话、同场核验、榜单读取、入库和重复运行。单独用临时 Windows 系统任务启动了独立工作进程，退出码为 0，并验证删除任务。官网已报名账号、近期打码解除、真实截图展示及平台会话寿命仍待参赛账号验收。

### 淘股吧数据核对记录（2026-11-22）

**截图证据。** GET 的 mode=screenshot 依据当前账号、赛事、赛组、交易日、版本、选手和字段定位本地截图。recognizeScreenshot 在 Windows 上调用系统 OCR，返回代码和带仓位标签的百分比候选。reviewScreenshot 在同一个 SQLite 事务内检查参赛范围和版本，存图、修订用户确认的字段并发布快照。图片以摘要去重，各字段保留对应图，旧快照照常读取。确认的仓位可参与仓位统计，完整持股或明确空仓可参与共同持仓；部分图保留可见证券。收益与主动报单人数使用原报单状态。原图入口指向本人登录可见的官网选手战绩页，具体日期栏决定所查看的原图。

**登录后的官方年赛。** 在普通登录、未报名账号上，年赛的「选手列表」可打开。「全部选手」显示 1,810 人，首页 50 行，共 37 页。页面另列独立资金组、星耀组、我的关注以及退赛／取消资格。全场榜为 DIV 行，表头依次为总排名、选手笔名、总收益、今资产、今收益、今存取、今交易、仓位、备注。「总排名」与可点击排序的「今收益」有不同含义。官网可显示高于 100% 的仓位，也有未报单行。参赛人数和当日应报人数分别处理。[官方年赛](https://www.tgb.cn/spmatch/matchAll?tid=2nPcAoCrpCL)

**历史持仓。** 切换 11 月 11 日后，榜单右上角显示「11-11更新」。同一选手该日「今交易」5 支，展开后实际为 4 条持仓、1 条卖出。持仓明细列出股票名称、当日涨幅、操作、数量和持仓金额。股票链接带 fullCode、spmatchSeq、lookeuserID 和实际交易日 dateNum。榜内选手战绩链接自身仍可带浏览当天的 dateNum，读取器用榜单更新日期与股票链接核对。只取持仓表内可确认代码的正数量证券；卖出表不进入收盘集合。只有今交易和仓位均明确空仓才据此确认为空仓。

**选手战绩页。** 选手摘要包含总收益、总排名、组内排名、初始资产、今资产、累计存取、今日／近 5 日／近 30 日收益及平均仓位。平均仓位与榜单当日仓位分开。持仓表按日期合并单元格，可按类别筛选，列有日期、今收益、今资产（存取）、股票名称、类别、数量、持仓金额及报单原图入口。抽查该选手 11 月 16–20 日可见收益，证券、操作、数量、金额均打星；11 月 13 日及部分更早记录可读。该窗口是本次样本观测。官网提示报单来自选手截图，收益尚未经官方验证。[抽查的选手战绩页](https://www.tgb.cn/spmatch/gains/readInfo?lookeUserID=12898867&spmatchSeq=881)

**读取与统计约束。** readContestDay.js 只在指定官网比赛页读取渲染的榜单，依次点「展开」「下一页」。中途切换账号、赛组、日期，或分页重复、超时、用户取消时停止，不发布半成品。人数与官网总人数、排名连续性同时吻合才声明完整。published 表示榜单当日披露且未出现明确的缺报或沿用提示，参与可见收益、仓位和完整持仓的比较。主动报单人数只计 reported。浏览器测试覆盖两页、早期拒绝未报名、历史日期、超满仓和卖出排除。近期参赛正例、官网书签兼容性与线上全场分页仍待有资格的账号实测。

**粘贴与分页。** 浏览器剪贴板提供带链接的表格时，在本地读取文本及官网选手链接，检查行内选手身份。公开参赛卡给出唯一战绩赛事序号时，将其与粘贴表中的战绩链接交叉核对。无链接的制表符表格沿用用户映射的稳定 ID，数据来源和交易日由导入者核对。用户在同一比赛、赛组、交易日内分批暂存，重复行按选手 ID 及内容核对，冲突则保留已暂存数据并提示。所有页组成一次预览，发布前不写入数据库。

**打码与历史版本。** JSON 和表格均将星号数值解析为缺失。持仓明细含遮挡时保留可见代码并标记部分可读。遮挡的身份无法导入，遮挡的排名无法用于声明榜单完整。首日报单允许收益和排名留空。导入预览记录当时的版本，同日有其他修订先发布时，过时的预览须重新核对，相同内容重试复用原版本。仅提供 asOf 的历史查询也按该时点查找已发布版本。

## 1. 接入分层与代码落点

数据流为「赛事授权数据／用户有权使用的导出文件 → 字段校验与标准化 → 本地版本快照 → 确定性指标 → 复盘视图」。数据获取与统计使用同一份标准化契约；文件和在线来源均保留来源类型。平台公开的比赛入口与早期规则仅证明业务形态，在线适配器的授权、分页、批量使用、历史深度及实际字段须用当前赛事验证。[赛事页](https://www.tgb.cn/spmatch/index/) · [规则说明](https://m.tgb.cn/a/1ykBDNwqjH8)

## 2. 先验证真实数据，再启用在线更新

1. 用一个已获权限的参赛账号确认赛事 ID、赛组 ID、同一选手跨日稳定 ID、证券标识、排名列表及参赛人数来源。分别记录榜单、日收益、累计收益、总仓位、持仓完整性、报单时间和状态的样例及单位。未知字段登记为 unavailable。
2. 对一场比赛两个相邻交易日记录平台支持的授权取得方式、允许的使用范围、分页终止标识、频率、授权失效及历史留存条件。核对首尾页、重名选手、缺报、空仓。记录某字段“个人页面可见”和“允许批量分析”各自的验证结果。按验证结果打开对应能力。
3. 如有合法导出，可先做文件适配。建议首个标准输入为 UTF-8 JSON：顶层含 schemaVersion、赛事、赛组、交易日、来源时间、覆盖声明、名册及报单数组。每条带源选手 ID、名次、报单状态、收益、仓位和持股数组；百分数单位由 schema 声明。导入预览给出识别字段、选手数、重复／冲突数及将发布的版本，用户确认后入库。真实导出格式通过映射进入同一契约。缺少名册的文件只可宣称文件覆盖人数。
4. 本机服务运行且通道授权有效时，按赛事配置的盘后取数窗口和来源允许的频率刷新；用户也可手动刷新。服务关闭期间的日期在下次启动时按可读历史补取。只有文件来源时显示“导入下一交易日”。不从赛事人数推断报单数，不硬编码早期规则中的次日定榜时间。

## 3. 存储、身份与时间

建议在现有 dataRoot 下建立私有 SQLite 库 `player-analysis/store.sqlite`，复用项目 Node 运行时的 SQLite 能力。按版本迁移并纳入本地数据备份。用 SQLite 事务发布，避免为每名选手单独读写台账。以下主键均受同一用户授权范围 scope 隔离。

| 实体 | 关键标识及字段 | 用途 |
|---|---|---|
| competition / division | scope、源比赛 ID、源赛组 ID、名称、时区、交易日历、能力、授权状态 | 一场多组。只有官方统一榜才提供全场排名。 |
| snapshot | snapshotId、scope、赛组、tradeDate、observedAt、sourceUpdatedAt、sourceKind、revision、内容摘要、rankComplete、coverage、previousVersion | 区分业务日、实际可见时间、更新和修订。默认取选定业务日最新可见版本。 |
| member_day | snapshotId＋sourcePlayerId、显示名、在赛／退赛、应报资格、官方名次和榜内顺序 | 保留当日名册与榜单覆盖范围，名称只用于显示。 |
| report | snapshotId＋sourcePlayerId、reportState、returnDay、returnTotal、nav、exposure、holdingsState、sourceRef、sourceReportedAt | reportState 区分实报、请假沿用、停牌沿用、缺报和未知；holdingsState 区分完整、明确空仓、部分遮挡和未知。 |
| holding | snapshotId＋sourcePlayerId＋symbol | 股票代码归一、同股计一次。个股权重为可空扩展字段。空表只有搭配明确状态才可解释为空仓。 |
| follow / job | scope＋赛事＋选手 ID；jobId、scope、任务键、状态、游标、进度、原因 | 跨日关注及幂等刷新。若来源 ID 仅组内有效，身份键增加赛组并限制跨组关联。 |
| analysis_ref | refId、scope、查询、依赖快照 ID 列表、算法版本 | 观察记录、摘要及分页下钻引用同一组快照。历史资料修订后仍能解释原值。 |

收益、仓位在契约内采用比例值（0.25 表示 25%），使用固定精度十进制或定标整数比较、聚合；页面最后一步格式化。交易日按 Asia/Shanghai 及赛事有效交易日历取前一日。明确允许的杠杆仓位单列超满仓，单位不明或不合来源约束的值标记无效。索引覆盖 scope／赛组／交易日／版本、快照＋股票＋选手、选手＋交易日，以及快照内排名顺序。

## 4. 统计契约

**分组。** T 为复盘日，P 为上一赛事交易日。全场使用 T 日在赛名册；领先／落后使用所选榜单日（默认 P）的官方累计收益榜。当期缺报或退出者保留组名额，分别显示可用人数与缺失原因。昨日分组成员在 T 已退赛的，今日指标排除。每次响应附两个榜单日期和各自覆盖情况。完整榜单人数 M，名额 k 为 N 或 ceil(M × p)，前后同时比较时至多 floor(M/2)；超限的自定义输入返回允许范围，默认 20 遇小组时自动显示实际 k。M 小于 2 时仅显示整体。并列按官方次序；边界次序未知或缺页影响成员身份时，将该组标为不可计算。

| 指标 | 计算和有效样本 |
|---|---|
| 报单覆盖 | 以 T 日应报名册为分母。主动报单、沿用和未报分别计数；来源未给出明确应报范围时返回人数及未知分母。持仓完整率单独计算。 |
| 盈利率、收益／仓位中位数 | 逐组用 T 日有效实报。盈利分子为日收益 > 0，分母为有日收益者；偶数样本取中间两值均值。仓位上升占比仅使用 T 和 P 均实报且仓位有效的固定成员。 |
| 共同持仓 | 令 H 为组内当日实报且持仓完整或明确空仓者。持有某股人数为 H 中该股唯一选手数，持有率为持有数除以 H 的人数。部分遮挡者仍可在选手详情看到可读部分。 |
| 偏好差 | 100 ×（领先组持有率 − 全场持有率），单位为百分点。分母为零返回 null。默认按差值降序、领先组持有人数降序、证券代码升序排列；每行显示两组人数与分母。 |
| 新增、继续、退出 | 固定所选组成员，取 T、P 均在赛且持仓完整实报者交集。逐人比较两个证券集合。仅 T 有为新增，两天有为继续，仅 P 有为退出；净增＝新增－退出。股票全集取两日并集。 |
| 近 5 日持仓演变 | 显示截至 T 的五个交易日。选手组沿用当前所选成员；每天独立展示该日持有率，当日变化用与前一日的可比交集。提示“按所选成员回看”，缺前一日只展示当日水平。 |
| 仓位分布 | 默认空仓 x=0、轻仓 0<x≤30%、中仓 30%<x≤70%、重仓 70%<x≤100%、超满仓 x>100%。组内占比使用有效仓位人数，未知另列。 |
| 盈亏分布 | 以日收益 r 划为 r≤−5%、−5%<r<0、r=0、0<r<5%、r≥5%。点击分桶用同一边界查名单。 |
| 排名迁移、连续在榜 | 比较 T 和 P 各自当日官方榜前 k 的 ID 集合，差集标新晋／跌出，交集标留榜。连续天数自 T 倒数，遇缺榜标已确认的下限。 |
| 近 20 日持续领先 | 对窗口内每个交易日独立按完整官方榜 ceil(M×10%) 取人。记录可判定名次天数、进榜天数和实报天数。持续领先表要求 20 日名次、实报和净值有效，按进榜天数降序、最大回撤幅度升序、选手 ID 排序；短样本仍可查看档案。 |
| 最大回撤 | 用窗口内按日排列的官方复权净值，或经核对同口径的 1＋累计收益。D=max(1−当天净值/截至当天的窗口内最高净值)，以正百分比展示。净值序列有缺口或峰值无效时标原因，个人档案显示实际观察窗口。 |
| 自选股摘要 | 按当前 watch 集合与所选日持有／变动股票相交。依次选偏好差最大的正值股、可比样本净增人数最多的正值股、关注选手当日新增持有者人数最多的股。同股合并、同值按代码排序、无事实则少出。显示分子分母、名单入口和当前自选口径。 |

零分母、历史不足、不可见、源数据无效各有 reason；观察到的零单独返回。仅能确认旧快照沿用或报单来源未知时，可展示平台名次与原始记录，排除当天实报样本。所有行为类措辞以收盘集合变化为限。

## 5. 接口、同步与异常

**查询契约。** 新视图 GET /view/player_analysis 接受 mode（matches、overview、stocks、players、player、members、digest、job）、match、division、date、rankBasis、groupSize 或 groupPct。下钻另带 refId、metric、bucket、symbol 或 playerId。列表采用稳定排序、版本游标，默认 50 行、上限 100 行。历史和明细约束在当前 scope 内。摘要读取现有 watch 台账；列表首次发布和用户调整自选后重新计算交集。

响应包含 context、dataState、coverage、capabilities、refId、rows、nextCursor。指标结构统一为 value、unit、numerator、denominator、excludedByReason、reason、membersQuery；中位数使用 value 和有效人数，numerator 留空。示例：某股领先组 6/18、全场 120/1500，差值行回传两套分子分母，展示 +25.3 个百分点；点击“6”只返回对应 6 人。服务端拒绝失效游标混读新版本，客户端提供重新加载。

**写操作。** POST /view/player_analysis 接受 addMatch、refresh、previewImport、commitImport、setFollow。预览返回文件摘要及短期 previewId；确认时重新核对账号范围及摘要。refresh 返回 jobId；setFollow 显式设置布尔值，可安全重试。只解析已支持的官方赛事链接或稳定 ID，接口、日志、来源引用不保存登录密钥。手动输入、导入和查询参数均校验类型、范围与大小。

**状态机。** 刷新任务依次进入 queued、running、published，或停在 partial、auth_required、failed。按 scope＋赛事范围＋交易日合并重复任务。按分页暂存与去重，校验覆盖后在一个事务内写入快照并切换当前指针；相同内容摘要复用已有版本。有效但覆盖不全可显式发布 partial，单次网络失败保留上次可用快照，缺页不得覆盖较完整同日版本。重试遵从来源限频，凭据失效暂停，服务重启核对游标和源版本；上游页面跨版本时重新读取。补报形成新 revision，按依赖快照 ID 重算后续跨日指标与窗口。

**权限与本地数据。** 每次读写检查数据所属授权范围；权限变化后按已核实的留存条件限制历史访问。比赛明细与关注名单放在模块专库，规则摘要在本地生成。通用 AI 台账、聊天上下文、遥测和发布包均排除选手明细；观察卡仅持久化用户确认的文字、股票、日期与不含选手明细的本地 refId。隐私模式沿用已有交互约束。

## 6. 交付顺序与验收矩阵

| 步骤 | 交付与需求 | 关键验证 |
|---|---|---|
| 1　接入与版本 | A1、A2。验证真实账号、字段与取得方式；建标准输入、预览、版本库及覆盖统计。 | 两个连续交易日与来源抽样核对。重复导入不增版本，修订新增版本；中断及断权不会混入另一场数据。 |
| 2　总览与分布 | A3、A4、E2。实现分组、指标及按分桶下钻。 | 30%、70%、100%、零收益和 ±5% 边界各归一个桶；分桶合计等于有效人数，分子与展开名单逐人一致。 |
| 3　股票与联动 | A5、A7、E1、E4。实现可比集合、偏好、股票时间轴、自选摘要、K 线与观察草稿。 | 换榜但持股不变时新增为零；遮挡和明确空仓落入不同样本。历史 K 线截止 T，保存草稿后能回到所引用版本。 |
| 4　选手与关注 | A6、E3。完成历史档案、迁移统计、20 日比较、关注名单。 | 仅 6 日历史显示实际天数；窗口净值 1.00、1.25、1.00 时最大回撤为 20%。跨日跌出、退出后关注关系仍保留。 |
| 5　整体验收 | 完成桌面与窄屏的两条产品验收路径。 | 模拟两千人、20 个交易日、每人每日 10 只股票。目标为本地已发布版本总览和首屏列表查询 P95≤1 秒；记录设备、版本、冷启动用时及至少 30 次热查询。实测在线支持范围另列。 |

**可手算的回归样例。** 同一固定组含甲乙丙丁。P 日持仓分别为 X、空、X、X；T 日为 X、X、空、遮挡。则 T 日完整样本 3 人，X 持有率 2/3；双日可比 3 人，新增乙、继续甲、退出丙，净增 0。丁只进入覆盖说明。再把原本两天都持 X 的戊引入今日前组：今日偏好榜的持有人增加，戊在今日成员的跨日比较中应为“继续”。该样例同时检查汇总、成员列表与摘要引用。

**发布记录。** 分别记录文件适配、真实账号在线更新、指标复算、集成回放、性能五项结果及所用版本。在线取得方式待核实时可先交付文件来源的可用范围；自动更新须以实际比赛从添加到跨日刷新的全过程验收为准。
